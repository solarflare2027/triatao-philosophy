# 完整正文静态页面

旧站仍用 `/#/…`，不删除、不新增重定向、不改理论内容。给不执行 JavaScript 的 AI 分享文章时使用 `/read/…/`。例如 `/read/becoming/identity/`、`/read/practice/`。`/read/` 是原首页的完整 HTML 副本，导航可到达文章；`sitemap.xml` 列出生成的全部页面。

## 发布流程

普通预览无需安装依赖。静态生成和浏览器验收需要 Node 20+ 与开发依赖：

```sh
npm ci
npx playwright install chromium
npm run generate:readable
npm run check
npm run test:readable
```

如果电脑已安装 Google Chrome，可用 `BROWSER_CHANNEL=chrome npm run generate:readable` 和同样前缀的测试命令。开发依赖只在本机使用，不上传 node_modules，不改变生产技术栈。

生成器启动独立本地预览，遍历当前页面里的公开路由链接，读取完整渲染 DOM，包括折叠内容。`readable-manifest.json` 记录每页正文哈希、HTML 哈希及现有源码哈希。修改现有源文件后，`npm run check` 会在静态副本未重新生成时失败。不要手工修改静态副本。

发布依然使用原来的完整 dist 上传、版本目录、原子切换和回退流程。新增 static pages 与现有脚本必须在同一版本发布。根据实际缓存情况刷新受影响路径或域名目录，再核对线上 HTML。仓库推送本身不会发布。

## 路由和体验

- 原 Hash 路由继续原样运行。app.js 只增加了“没有 Hash 时读取静态页 data-read-route”的分支；普通页面没有该属性。
- 新页面 HTML 已包含全文，无 JS 也可读。原有模块运行时重新创建交互 DOM，保留菜单、搜索、动画、折叠、目录等。
- 新页面的跨篇链接使用独立静态 URL，通过浏览器导航。原站仍使用原有 Hash 导航。新页专用 readable.js 不在旧站加载。
- 带 `?layer=` 等参数的新页面把查询交给原初始化逻辑，正文仍完整提供。
- 不运行 JS 时，动画初始隐藏状态解除、目录改为普通锚点、原生 details 仍可展开。没有 JS 的搜索和筛选按钮不显示；这不影响正常浏览器的原功能。
- 未定义路径继续返回 404。服务器已有目录 index.html 支持，无需修改 Nginx 或安全设置。
- Hash 不会传给服务器，不能承诺旧 Hash 链接在所有不执行 JS 的 AI 工具中定位某篇正文。请分享新独立链接。

## 内容维护

继续编辑现有正文模块；新增练习继续按 PRACTICE.md 配置。生成器从现有路由链接发现页面，新增可公开访问但没有任何入站链接的孤立页面时，先在现有目录添加入口或在生成器 seeds 中明确登记。不得通过生成器编造正文。历史文件不会被生成器清空；撤下旧网页另行处理。

## 验收

测试 77 页（数量随公开目录增长）的无 JS 完整正文哈希、标题、canonical、锚点；代表页面在桌面/手机、新旧路由的显示、折叠、移动菜单、理论实践双向链接及未知路径 404。截图和 JSON 在 outputs/readable/，不提交私人运行输出。

上线后另用实际 AI 网页读取工具检查文章中段、结尾等独有内容。HTTP 200、sitemap 正确或本机浏览器成功不能单独替代 AI 读取验收。不同地区访问是抽样验证，不是长期稳定性的保证。

## P0 尚需的外部证据

现有部署账号无法读取 Nginx 访问日志；缓存密钥无 EdgeOne 站点配置查询权限。历史超时仍需错误发生时间、地区/运营商以及对应边缘/源站日志来归因。没有据此改动防火墙、WAF、地域/IP规则或服务器。
